# AGENTS.md — Customer Churn Prediction (Telco)

## Quick start

```bash
uv sync                               # install deps + editable churn package
uv run python scripts/generate_chart_data.py   # regenerate dashboard data (slow, see below)
uv run python scripts/train_model.py           # train + persist the demo-app model artifact (models/)
uv run streamlit run streamlit_app.py          # run the production-system demo app (Streamlit)
```

- Python >=3.14, package manager is **uv** (not pip/poetry). `churn` is installed editable via the hatchling build in `pyproject.toml` (`packages = ["src/churn"]`).
- The Streamlit demo app (`streamlit_app.py` + `app_pages/`) reproduces a production churn system: train/serve artifact separation, batch scoring of a simulated current customer base, confidence-band risk tiering, and an action queue. It loads artifacts from `models/` generated by `scripts/train_model.py` — run that once before launching the app. The app shows a hint if artifacts are missing.
- The static deliverables are self-contained HTML dashboards (`dashboards/telco_churn_financial.html`) that render from an embedded `const COST_DATA = {...};` block.

## Demo app wiring

- `scripts/train_model.py` uses the notebook's PR-AUC-tuned LGBM params (`Model.ipynb` cell 11) through `make_pipeline`, so the serialized `churn_lgb.joblib` bundles the ColumnTransformer — fully self-contained for inference.
- The "current customer base" is the 30% stratified holdout; the app hides its `Churn` label from the scoring view and only joins it back for the offline-validation tab.
- Risk tiers use fixed confidence bands (`Low <0.30`, `Medium 0.30–0.70`, `High >0.70`). The intervention playbook (`TIER_PLAYBOOK` in `app_utils.py`) is grounded in the notebook cost model: the only priced retention action is the 6-month / 20% discount offer at `FP_COST` per customer, low-risk customers get no action, and the cost-optimal threshold (~0.17) means the offer reaches most of the base.
- Caching: pipeline via `st.cache_resource`, scored base / model card via `st.cache_data`. Charts are Altair. Follow Streamlit skill best practices (no `use_container_width`, `width="stretch"`, `st.navigation`, sentence casing).

## Pipeline wiring

- `generate_chart_data.py` is the only runner. It computes RF (5-fold CV) and LightGBM (Optuna nested-CV) OOF probabilities, builds `COST_DATA` via `report.py`, writes `generated_cost_data.json`, and **patches the `COST_DATA` block inside the HTML** with a regex. Run it from the repo root so `import churn` resolves.
- The script has inline verification pins (cost mins, savings range, best-threshold drift window) that mirror `notebooks/Model.ipynb` headline numbers. It **exits nonzero** (`SystemExit`) on drift — that's the de-facto test suite.
- It's expensive: 5 outer folds × 50 Optuna trials + RF CV (minutes). Don't run it casually to "test" a change.
- `report.py` computes the REVENUE KPI block from the cleaned dataframe (`build_revenue(df)`); the same KPIs are still hardcoded inside the `REV_DATA` block in the HTML.

## Conventions

- Scripts are ports of notebook cells; docstrings cite the exact cells (`notebooks/Baseline.ipynb cell 43`). Keep logic in sync when editing either.
- Estimator step in every pipeline is named `model` (`MODEL_STEP` in `models.py`) so tuning uses `model__<param>` — don't rename it.
- `load_data()`: object cols → `category` dtype, `SeniorCitizen`/`Churn` → bool, `TotalCharges` coerced to numeric with NaN rows dropped, `customerID` dropped. `Churn` ("Yes"/"No") → bool.
- `make_pipeline(X, preprocessor, model, **kwargs)`: `model` is `"rf"` or `"lgb"`; default kwargs set `random_state=42` / `seed=42`.
- `cost.py` `rate_key()` formats retention rates as JS-safe strings (`0.45` → `"0.45"`, `1.0` → `"1"`) — the HTML renderer keys on these exact strings.

- For the Streamlit app, run the headless smoke test: `uv run streamlit run streamlit_app.py` and click through the three pages (or drive pages with `streamlit.testing.v1.AppTest`).
